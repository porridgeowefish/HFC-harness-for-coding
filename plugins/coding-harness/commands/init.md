In the current project directory, the top-level natural-language Skill is the primary entry. The main Agent scans the complete visible tree, then the runtime writes the path-only skeleton. It dynamically assigns disjoint source paths to `business-knowledge-writer` and `engineering-knowledge-writer`; they write only their owned knowledge documents. After engineering paths exist, the business writer creates `业务入口.md`; `rules-writer` then writes only the five Rules. `docs/knowledge/文件树.md` is written only by the runtime, once after the fact writers complete, and the runtime renders `component.svg` from the engineering writer's `component.puml`. The CLI is a deterministic fallback: `node "${CODEBUDDY_PLUGIN_ROOT}/bin/harness.mjs" init --phase prepare` writes static navigation and the path-only tree, while `init --phase finalize --knowledge <runtime-draft>` applies the completed facts after the checklist conversation. Its console result is deliberately compact and never prints the complete source inventory. When subagents backfill files between phases, prepare and finalize must remain in the same top-level orchestration session; a standalone finalize without that session context fails closed on existing long-lived assets instead of overwriting them. Do not add a digest, hash, CAS or second review round. A single administrator commits the shared contracts to Git; other members pull them.
