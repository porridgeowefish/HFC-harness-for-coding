## 3. 0.8 初始化与开发契约链路

1. 主 Agent 先触发侦察 subagent，对所有可见文件和目录做全量扫描（只排除 `.git`、`node_modules` 和机器运行态），写入 `文件树.md` 路径骨架。
2. 主 Agent 根据实际树建立会话内依赖图和唯一文件所有权；工程/业务 subagent 只读取并写入自己的不重叠范围，同时回写对应树项的真实用途。
3. 汇总 subagent 等所有可读路径完成后写 `项目总览.md`、`业务入口.md`、组件图源和 SVG；Rules subagent 等知识入口落盘后写五份 Rules。失败任务只重派相应负责人和未开始下游，不增加中间人工审核回合。
4. 顶层自然语言 Skill 逐项引导管理员确认八项 checklist；确认记录由运行时写入 JSON，用户不编辑 JSON。
5. 草案无占位符、文件树全部覆盖、八项 checklist 全部确认后，应用一次写完除 workflow 外的长期资产；应用入口在写入前再次校验 checklist，架构图同时保留 `component.puml` 与 `component.svg`。prepare、subagent 回写和 finalize 必须属于同一顶层编排会话；脱离会话对既有长期资产 fail-closed。

CLI 是上述 Skill 的确定性兜底；`phase=prepare` 只生成可识别的路径骨架，`phase=finalize` 才允许写入完成态知识。subagent 直接回写时，两个阶段必须在同一编排会话中完成。

设计阶段在 `design-decision.md` 后生成 `development-contract.md`，从五类模板中只装配适用契约块，再生成引用契约 ID 的 `task-package.md`。设计批准和进入开发都要求契约完成且结构合法；每个开发任务读取同一契约，变更契约必须退回设计并重新确认任务包。

## 4. Markdown 结构合同

- `CODEBUDDY.md`：`项目导航`、`阅读顺序与上下文边界`、`Rules 装配索引`、`全局行为规则`。
- `项目总览.md`：`项目用途`、`技术栈`、`软件设计架构`、`启动、构建与测试入口`、`顶层模块`、`未识别项`、`事实依据`；架构章节紧跟技术栈。
- `文件树.md`：探索态路径行不带说明；完成态每个可见文件和目录均有基于实际阅读的一句话用途，拒绝泛化套话。
- `业务入口.md`：五列表头为业务问题/场景、业务模块/功能点、优先阅读的业务知识、工程知识入口、源码/配置入口。
- 工程模块：模块定位、目录与入口、核心组成、主要流程、跨端关系、兼容边界、生效机制、易误判点、事实依据。
- 功能描述：所属业务模块、当前状态，以及当前功能、业务规则、边界、主要流程、事实依据；无历史时明确写“当前没有已验收的历史变化”。
- Rules：首行 `适用场景:`，随后必须遵守、相关知识入口、验证方式、更新门槛；只做执行约束和知识索引，不复制知识正文。
- 共同开发契约：契约范围、契约清单、一个或多个按需类型块、全任务共同门禁；契约清单的 ID 与类型必须和类型块一一对应。
- 任务包：可重复出现多个任务节，每个任务必须声明负责/使用的契约 ID，并读取需求、设计结论和共同开发契约。

`runtime/markdown-contract.mjs` 对标题层级/顺序、表头与分隔符、逐文件允许占位符、完成态路径覆盖、证据安全、Rules 适用范围与知识链接、泛化用途执行结构 allowlist；黑名单只保留为补充诊断，不能代替合同证明。

## 5. Hook 作用域

`detectHarnessScope` 只认有效 `.codebuddy/harness.json`：

- `managed`：继续执行状态写保护、共享契约忽略保护和 preCommit 门禁；
- `broken`：孤立 checklist 或无效配置，fail-closed 给出修复提示；
- `absent`：SessionStart 与 PreToolUse 完全 no-op，不读取 Harness 状态、不执行门禁。

已接入项目的状态保护对字面量路径、Shell 变量、环境变量访问、复合命令、重定向、复制/移动/解释器写入均 fail-closed，仅保留单一只读检查命令；状态写入统一经 transition runtime。
