# V6 初始化与知识导航合同

> **历史版本（非现行合同）**：V6 已被 0.7.0 的动态 subagent 初始化与 Markdown 结构合同取代。保留本文只为追溯；不得按本文旧字段、旧单宿主编排或其他已废止方案生成新项目资产。

## 目标

让首次接入在创建任何 workflow 前完成可审阅、可直接供人阅读的长期项目文档；使用者由顶层 Skill 引导完成确认，不必理解或手工编辑 checklist JSON。

## 不可变约束

- `docs/workflows/` 与 `.codebuddy/workflows/` 是唯一按需创建的 workflow 区域；其余规范长期资产必须在初始化应用时写完。
- 初始化读取顺序固定为：对每个可见项目文件的全量扫描与文件树骨架 → 已有项目文档 → 文件树所列每个可读项目文件 → 项目总览 → 业务入口 → 架构图 → 工程模块 → `docs/function/` → Rules；不得预设 README、`docs/`、目录名或扩展名才是原始材料位置。
- 每次 workflow 创建也必须先将同一全量扫描结果写入 `source-materials.md`；用户原话、链接和外部材料仅作为追加定位项，不复制正文。
- 文件树始终是 Markdown 导航：每个可见项目文件或目录保留一条树形记录和一句用途说明；后续分析只能补充该说明，不能改成散文或只列关键文件。
- `component.puml` 是版本化源图，`component.svg` 是同一轮初始化默认生成、面向人的可视 SVG；两者均进入 Git。
- 不产生未在技术设计登记的初始化产物，尤其禁止 `gates.md`、`harness-self.md`、`核心约束.md`、`启动入口.md`。不登记额外“辅助说明”目录或 Markdown。
- 功能知识必须主动构建：每个识别到的业务模块都有 `function.json`，每个功能点都有 `功能描述.md` 与 `功能演变历史.md`；无法确定时由顶层 Skill 向管理员追问，不写完成态占位文档。
- 不引入 digest、内容哈希、CAS、跨进程初始化锁或第二套确认链；管理员串行初始化并用 Git 共享确认后的契约。

## 顶层 Skill 交互

1. 说明“正在生成全量文件树”，运行只读扫描；展示项目入口、无法读取的文件和识别风险。
2. 按树索引先读取现有文档，再逐个读取可读项目文件，汇总用途、业务功能、工程模块、启动/构建入口和组件关系。
3. 展示长期文档草案与八项非技术化确认问题；逐项收到管理员确认后，Skill 调用受控 CLI 写入 checklist，而不是要求用户编辑 JSON。
4. 只有草案没有未决项目事实、八项确认均已记录时，才应用全量长期资产；随后提示管理员检查并提交 Git。

## 验收

- 初始化测试证明：文件树先存在且列出完整树；知识草案按树中项目文件回填用途；无 workflow 时所有其他规范资产均为实际内容、无 `<...>` 占位。
- SVG 测试证明：应用知识草案后 SVG 包含可读标题和来自组件图的节点/连线文本，且是有效 XML；PlantUML 不可用时仍生成可阅读的结构化 SVG。
- 顶层 Skill、CLI 与 tests 证明 checklist 的逐项引导/写入链路，且 doctor 的 Git 共享契约检查不变。
- 包校验拒绝未登记的模板、运行时文件或生成文档名称；全套测试与包校验通过。
